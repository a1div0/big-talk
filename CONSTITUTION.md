# Конституция проекта

Это правила о том, как *репозиторий* принимает решения. Не путать с содержимым `spec/` —
это правила о том, как принимает решения *проектируемая система*. Нам нужна собственная
конституция ровно потому, что мы не можем оправдать процедуру, по которой сами не живём.

# Идеи, на которых всё держится

1. **Ценности входят только через `axioms/`.** Всё остальное выводится. Аргумент «потому что
   так правильно» без ссылки на аксиому — дефект.
2. **Тестовый слой больше спецификации.** У политической системы нет рантайма; единственные
   «запуски» — мысленные тесты, прецеденты и агентные прогоны.
3. **Нормативный текст — это код, спецификация — замысел.** `normative/` порождается из `spec/`
   и проверяется на соответствие, как код на соответствие спеке.
4. **Путь к пилоту** -- это отдельный проект в отдельном репозитории

# Идентификаторы и статусы

| префикс | тип | статусы |
|---|---|---|
| AX | аксиома | draft → proposed → accepted → deprecated |
| REQ | требование | draft → proposed → accepted → deprecated |
| EL | элемент | draft → proposed → accepted → deprecated |
| ADR | решение | proposed → accepted / rejected → superseded |
| PREC | прецедент | draft → accepted / disputed |
| ACT | актор | draft → accepted |
| THR | угроза | open → mitigated / accepted |
| DIS | разногласие | open → addressed / accepted |
| ASM | допущение | draft → accepted → falsified |
| TEST | тест | draft → accepted → deprecated |
| RUN / SIMRUN | прогон | done |
| SIM | сценарий | draft → accepted → deprecated |
| NORM | нормативный текст | draft → proposed → accepted → deprecated |
| DEF / OQ | дефект / вопрос | open → resolved / wontfix |
| RISK | принятый риск | accepted → retired |

Номера не переиспользуются. Удалённый артефакт получает статус deprecated, а не удаляется:
ссылка на него из старого ADR должна оставаться разрешимой.

# Глоссарий

Термин в AX/REQ/EL/NORM/TEST пишется как `[[термин]]` или `[[термин|форма в тексте]]` и обязан
иметь заголовок `## термин` в `GLOSSARY.md`. Неопределённый термин — ошибка. Определённый, но
неиспользуемый — предупреждение. Оценочные термины («разумный», «добросовестный») без процедуры
их установления не проходят TEST-004.

## Бюджет сложности

`budget.yaml`: объём спецификации и нормативных текстов, число элементов, ролей, глубина
зависимостей, число исключений. Ориентир: гражданин читает за вечер, должностное лицо
исполняет без юриста.

# Структура

```
big-talk/
├── CONSTITUTION.md     правила, по которым живёт сам репозиторий
├── GLOSSARY.md         термины; [[термин]] в тексте обязан быть определён здесь
├── budget.yaml         бюджет сложности — превышение = красный CI
│
├── axioms/        AX    ценности-входы
├── requirements/  REQ   проверяемые требования, выведенные из аксиом
├── spec/          EL    элементы конструкции — то, что проектируем
├── adr/           ADR   почему именно так: отвергнутые альтернативы, принятые риски
├── precedents/    PREC  исторические случаи с источниками и уверенностью в причинности
├── actors/        ACT   роли, группы, внешние акторы: интересы, ресурсы, медианное поведение
│   └── threats/   THR   векторы атаки: кто, чем, сколько стоит
├── dissent/       DIS   карта разногласий: чей интерес ущемлён и что он будет делать
├── assumptions/   ASM   допущения о людях/технике/экономике и что ломается, если они ложны
├── tests/         TEST  мысленные тесты
│   └── runs/      RUN   результаты прогонов
├── sim/scenarios/ SIM   сценарии агентного моделирования
│   └── runs/      SIMRUN результаты прогонов с логами
├── normative/     NORM  нормативный текст, реализующий элементы
├── registry/      DEF OQ RISK   дефекты, открытые вопросы, принятые риски
│
├── skills/              скиллы для агентов
├── templates/           шаблоны всех типов артефактов
├── schemas/README.md    схемы frontmatter и список инвариантов
├── tools/lint.py        линтер графа, матрица прослеживаемости, граф, бюджет
├── tools/new.py         создать артефакт из шаблона со следующим номером
└── .github/workflows    CI: lint на каждый push и PR
```

# Слои и что откуда выводится


```
AX (ценности, вход) → REQ (проверяемые требования) → EL (конструкция) → NORM (текст закона) → TEST
        ↑                     ↑                          ↑
       DIS                  TEST                        ADR ← PREC, ASM, THR, DIS
```

Ценности входят в проект только через `axioms/`. Всё остальное — инженерия от аксиом.
Если в ADR встречается аргумент «потому что так правильно» без ссылки на AX — это дефект ADR.

# Как всё связано

Каждый файл — markdown с YAML-frontmatter. Связи — только через ключи frontmatter со списками
id. Линтер проверяет, что граф замкнут:

```
AX ──derives_from──▶ REQ ──satisfies──▶ EL ──implements──▶ NORM
 ▲                    ▲                  │ ▲
 │                    │            decided_by  targets
DIS                 TEST ──verifies──┘ ADR ◀── PREC, ASM
                      │                  │
                     RUN ──findings──▶ DEF/OQ ──resolved_by──▶ ADR ──▶ RISK
                                         ▲
THR ──mitigated_by / accepted_as──▶ EL / RISK
```

Полный список ключей, статусов и инвариантов — `schemas/README.md`.

# Стандарт доказательств

- Прецедент без источников не принимается. Прецедент с `causal_confidence: contested` может
  использоваться в ADR только с указанием обеих интерпретаций.
- Один прецедент не обосновывает решение. Минимум — два прецедента с разным исходом или один
  прецедент плюс явное допущение (ASM), объясняющее, почему наш случай похож.
- Находка симуляции не является доказательством. Она становится доказательством, когда переведена
  в мысленный тест, который человек может проверить без агента.

# Чего методика не делает

- Не решает, кто пишет аксиомы. Это политический вопрос; методика делает его видимым, а не снимает.
- Не доказывает, что система будет работать. Она делает проверяемым, *почему мы так думаем*,
  и *что именно* мы не проверили.
- Не защищает от Гудхарта на саму себя: команда начнёт оптимизировать прохождение CI.
  Против этого — квартальная проверка, которую нельзя автоматизировать.

# Definition of Done

**EL → accepted**, только если:
1. `make lint` зелёный;
2. есть принятый ADR;
3. все применимые TEST имеют прогон с `pass`, либо каждый `fail` закрыт ADR или принят как RISK;
4. есть NORM со статусом не ниже proposed и таблицей соответствия;
5. все THR с `targets` на этот EL имеют митигацию или RISK;
6. все DIS с `affected_by` на этот EL имеют статус addressed или accepted.

## 6. Защита от Гудхарта на саму методику

Раз в квартал мейнтейнер, не участвовавший в разработке за квартал, читает `spec/` целиком
как гражданин — без линтера, без чеклиста — и пишет заметку «что здесь не так». Заметка
превращается в OQ. Это единственная проверка, которую нельзя автоматизировать, и потому
единственная, которую нельзя пропустить.

## 7. Язык

Документы и нормативный текст — русский. Идентификаторы, ключи frontmatter, код — английский.
