# draft-normative

## Принцип
NORM — это «код», EL — «спека». Каждая статья ссылается на пункт правил EL. Расхождение —
дефект: либо NORM неверно реализует EL, либо EL неполон и это надо вернуть в spec через ADR.

## Процедура
1. Прочитай EL целиком, GLOSSARY.md, `deploy/host-interface.md` (язык и уровень нормы хоста).
2. `python tools/new.py normative <slug>`, `implements: [EL-…]`, `level` по типу нормы.
3. «Текст»: статьи. Правила:
   - одно правило EL → одна или несколько статей, не наоборот;
   - «Поведение при неисполнении» EL → обязательно отдельная статья с явным сроком и субъектом;
   - термины — из GLOSSARY.md, определения выносятся в первую статью;
   - нет статей, которых нет в EL. Если норма нужна, а в EL её нет — OQ и стоп.
4. «Соответствие спецификации»: таблица статья ↔ пункт EL ↔ расхождение. Каждый пункт EL должен встретиться. Каждая статья должна ссылаться на пункт.
5. «Интерфейс с хост-правом»: что затрагивает, что требует изменения хоста. Сверь с `deploy/host-interface.md`.
6. Для обратной проверки (текст → спека): построй ту же таблицу от статей и выпиши статьи без пункта EL и пункты EL без статьи. Это DEF на NORM или OQ на EL.
7. Обнови EL: `normative: [NORM-…]`.
8. `python tools/lint.py check`.

## Чего не делать
- Не «улучшать» правило при переводе в статью. Улучшения — через ADR.
- Не использовать оценочные термины («разумный», «соразмерный», «добросовестный») без процедуры их установления — это дефект по TEST-004.

## Выход
Путь к NORM, таблица соответствия, список расхождений.
