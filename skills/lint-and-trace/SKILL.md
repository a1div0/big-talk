# lint-and-trace

## Процедура
1. `python tools/lint.py check`. Прочитай все ERROR и WARN.
2. Для каждой ошибки — классифицируй:
   - **механическая** (опечатка в id, файл не в том каталоге, нет обязательной секции с пустым содержимым) — чини сразу;
   - **содержательная** (REQ без TEST, EL без ADR, THR без митигации, ASM без if_false) — не выдумывай содержание. Создай OQ с `affects` и оставь ошибку, либо запусти соответствующий скилл (`write-adr`, `red-team`, …) и скажи пользователю;
   - **термин вне глоссария** — добавь определение в GLOSSARY.md, только если оно однозначно следует из контекста; иначе OQ.
3. `python tools/lint.py budget`. При ≥90% любого лимита — OQ «что сокращать».
4. `python tools/lint.py matrix`. Найди REQ с пустыми колонками «элементы» или «тесты» — это непокрытые требования, доложи явно.
5. Повтори `check`. Доложи, что осталось красным и почему.

## Чего не делать
- Не удалять ссылки, чтобы убрать ошибку «висячая ссылка». Найди или создай цель.
- Не переводить статусы в accepted, чтобы пройти проверку.
- Не расширять budget.yaml. Бюджет меняется только через ADR.

## Выход
Вывод линтера до и после; список созданных OQ; матрица с отмеченными пробелами.
