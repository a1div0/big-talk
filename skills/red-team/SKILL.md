# red-team

## Принцип
Не «можно ли сломать» — всё можно. «Сколько стоит» и «кто заметит».

## Процедура
1. Прочитай EL, его `depends_on`, ACT с ресурсами, PREC с тегами amendment / emergency-powers / quorum / electoral-commission.
2. Пройди каталог векторов, для каждого — применим ли к элементу:
   - захват органа, считающего результат;
   - изменение регламента/толкования вместо правила;
   - перенос сроков, срыв кворума, массовая отставка;
   - чрезвычайный режим как обход;
   - буквальное исполнение с отменой цели;
   - захват через кадры (назначить своих на срок дольше своего);
   - внешний актор (хост, соседи, капитал) через legal-канал;
   - салями: необратимое через серию обратимых.
3. Для каждого применимого: `python tools/new.py threat <slug>`. «Сценарий атаки» — пошагово, с пометкой законный/незаконный, наблюдаемый/скрытый на каждом шаге. `capability_required` — конкретно: сколько должностей, какое большинство, сколько месяцев.
4. «Стоимость атаки» — в единицах, сопоставимых между THR (это вход для TEST-010).
5. «Митигация» — какие пункты правил повышают стоимость. Если никаких — `status: open`, `mitigated_by: []`, и это блокер для accepted.
6. Найди самый дешёвый вектор и напиши это в выходе явно.
7. `python tools/lint.py check`.

## Чего не делать
- Не митигировать сам. Красная команда находит, `write-adr` решает.
- Не ограничиваться незаконными атаками. Самые опасные — законные.
- Не оценивать «вероятность» — оценивай цену. Вероятность — функция цены и выгоды, её посчитает тест.

## Выход
Список THR, отсортированный по стоимости, самый дешёвый — первым.
