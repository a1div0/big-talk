# stakeholder-roleplay

## Принцип
DIS пишется так, чтобы актор подписался под «Позицией актора». Это не наша оценка его интереса,
а его собственная. Карикатура на оппонента — дефект DIS.

## Процедура
1. Выпиши всех ACT (role, group, external). Если для очевидно затронутой группы нет ACT — создай через `tools/new.py actor`.
2. Для каждого ACT прочитай интересы и ресурсы. Прочитай целевой EL/ADR/AX.
3. Спроси от лица актора: что я теряю по сравнению со статус-кво? По сравнению с альтернативами из ADR? В своих терминах, не в терминах проекта.
4. Если потеря есть — `python tools/new.py dissent <slug>`. `harm` — в терминах актора. `likely_response` — конкретно: саботаж какого шага; обход через что; выход куда; оспаривание где. С оценкой цены и вероятности.
5. «Что мы с этим делаем» — не заполняй сам, если нет ADR. Оставь статус open. Решать — через `write-adr`.
6. Отдельно проверь аксиомы: есть ли актор, для которого сама AX неприемлема? Такая DIS привязывается к AX через `affected_by` и добавляется в `dissent` аксиомы.
7. `python tools/lint.py check`.

## Чего не делать
- Не писать DIS «в целом». Один актор, один элемент, одна потеря.
- Не смягчать `likely_response` до «будет недоволен». Что именно сделает.
- Не закрывать DIS без ADR.

## Выход
Список DIS с краткой сводкой: актор → потеря → вероятное действие.
